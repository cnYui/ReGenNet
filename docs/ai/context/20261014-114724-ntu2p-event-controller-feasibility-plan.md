# 事件控制器的可行性检查计划

前置设计：`20261014-113544-ntu2p-event-controlled-dct-diffusion-candidate-design.md`。本文件在新的事件控制实现前创建；C3/C4 仍在训练，不能据尚未完成的结果更改其配置。

## 决策问题

软图消息不能保证受动者在接触后才开始响应。若继续采用接触控制路线，必须直接重建 B root，而不能把接触门叠在已有提前后退的先验上。先验证最小解码器是否具备这个保证、在现有数据上是否有合理的表示上限，再决定是否训练更多架构。

## 本阶段范围

- 新增纯 torch 函数式解码器，不改 C1–C4 模型、损失或正在运行的训练。
- 输入为 obs、先验的两人 root-relative 轨迹、自由/接触路线、B 响应速度；接触路线从 obs 重建 B 水平 root，obs 末五帧速度轻衰减延续，新增响应在六段掌腕—躯干距离≤0.20 m 连续三帧之后按三帧平滑包络积分。所有几何以最终投影后局部轨迹为准，当前帧接触只影响其后位移。
- 非接触路线原样输出；已有观测运动不应被锁死。主阈值 .20，敏感性 .15/.25/.30 全报。
- 合成干预验证：移动 A 手可改变接触起点；无接触时新增响应为零；已有 B 运动仍可持续；首次预测与 obs_last 严格相同；骨长保持；最终输出接触前无新响应。
- 只在 train 统计弱路线标签、受试者覆盖和 oracle 表示误差。可另在 H-val 上运行固定非学习型诊断（只使用 obs 与原 FD2 预测的速度控制），不把它当新训练模型，不用 test，不从阈值中择优。

## 继续/停止依据

若合成保证不成立，修正实现；若固定 .20 路线在训练中大量没有预测接触、或保留腿轨迹时明显增加脚滑/无法保留主线精度，不直接训练整套事件模型。应记录不可识别性与 root—脚状态解码的必要性，避免以自由路线吞掉失效案例。若 oracle 合理且部署诊断有潜力，再新建实际训练矩阵、预算、标签与图/扩散消融计划。

这一阶段仅检查可行性，不声称已经解决用户的两项目标，也不宣称真实皮肤接触或物理因果保证。
