# 最小接触事件 root 控制器：可行性结果

## 决策

结构保证成立，**不支持把“固定门+保留 FD2 腿轨迹”直接送入完整事件模型训练**。训练 GT 局部姿态的 oracle 表明事件中心控制有合理表示上限；实际 FD2 手部轨迹却在固定 .20 m 门下有 3/12 推人窗口始终无法接触，强制接触路线使 mpjpe +6.1%、B 水平 root RMSE +30.9%、掌—身体距离 RMSE +16.3%。必须先处理手部到达与 root—脚状态共同解码；不能通过自由路线排除这三条失败案例来声称改进。

依据实施前计划 `20261014-114724-ntu2p-event-controller-feasibility-plan.md`，只新增函数式模块、检查脚本、诊断产物与本文。没有改 C1–C4 模型/训练配置，没有读取 C 候选成绩，没有 GPU 训练或 test 检查。

## 实现

- 模块：`utils/ntu2p_event_control.py`。
- 检查：`scripts/check_ntu2p_event_control.py`。
- 结果：`results/forecasting/ntu120_label/ntu2p_graphdiff_research/event_control/feasibility.json`。
- 逐窗口 train 标签：同目录 `train_weak_label_records.json`。
- 固定诊断数组：同目录 `fixed_pushing_val_arrays.pt`。
- 全部 12 例接触/后退曲线：同目录 `all12_fixed_gate_contact_retreat.png`，不按改善择例。

核心接口 `decode_event_root(obs,root_relative,prior_roots,response_velocity,contact_route,...)`：local `[B,T,2,55,3]`、root `[B,T,2,3]`、B response `[B,T,3]`（m/s）、route `[B] bool`。可选 projector 在解码前投影局部姿态，之后每人刚性平移；用于门的几何就是最终输出几何。`event_control_from_prior` 接受原绝对 FD2 预测，自由路线 `torch.equal` 原样返回，不混合门。

接触路线直接从 obs 末帧重建 B 水平 root；obs 末五个独立平滑帧差的平均水平速度按 2.5 s 指数时常衰减延续。竖直 root 摆动与局部姿态沿用先验；A 的 root 沿用先验。固定六段掌腕—躯干中心距离 ≤.20 m 连续三帧时触发前缀事件；不累计无限小软概率。响应包络前三帧为 0/.5/1，速度积分只改变下一帧位置。观测已接触时继承事件，重复的 obs_last/future_first 不算新证据。

`prior_response_velocity` 只从 obs 与原 FD2 的平滑 B root 速度获得固定候选控制，不读 GT。`oracle_event_root` 显式读取 GT 局部姿态与下一帧 root，只用于表示上限；同函数可将得到的控制截为 DCT8，不能将该输出送进正式预测评分。

## 合成保证

CPU / torch 1.7.1 下检查通过：

| 检查 | 结果 |
|---|---:|
| 首预测帧严格等于 obs_last | `torch.equal` |
| 自由路线逐位不变 | `torch.equal` |
| 骨长最大绝对误差 | 3.33e−16 m |
| 最终输出与触发用接触距离差 | 0 |
| 首次持续接触 / 首次非零响应控制 | 28 / 29 帧 |
| A 手提前 7 cm 后首次响应控制 | 23 帧 |
| A 手滞后 7 cm 后首次响应控制 | 36 帧 |
| 无接触时新增响应 | 严格 0 |
| obs 已有 0.3 m/s 运动的 future 位移 | 0.437 m，未被锁死 |
| 改未来控制对输出前缀影响 | 严格 0 |
| 接触后响应控制梯度 | 有限且非零 |
| obs 已有接触 | 可继承并响应 |

控制在第 29 帧非零，首次输出位移影响第 30 帧；接触当帧不能反向影响已经输出的位置。响应门是离散机制，没有通过它对手部触发时间的连续梯度；未来如训练，必须独立监督连续接近几何与事件标签。

保证限定于新增响应通道；已有 obs 运动与竖直摆动仍允许，骨架中心距也不等于真实皮肤接触。这个控制器没有脚状态/锚定，不能声称解决步态。

## Train 标签与 oracle（仅 train）

只抽 train 中每条推人序列的开始/中心/结束 60 帧窗口，重复起点只取一次。共 299 窗、109 个独立序列、14 个受试者；约 29 s CPU 完成。受试者为 P001/P002/P005/P008/P009/P013/P015/P016/P017/P018/P019/P025/P028/P035。

事件标签复用既有六段距离评价逻辑：未在 obs 接触/后退，未来持续接触与持续退后时刻差在 −2..12 帧，退后速度 .10 m/s；双向平滑仅用于离线标签。没有按 val 挑阈值。

| 距离门限 | 可靠重叠窗 | 独立序列 | 独立受试者 |
|---|---:|---:|---:|
| .15 m | 126 | 51 | 13 |
| .20 m | 123 | 54 | 12 |
| .25 m | 91 | 42 | 11 |
| .30 m | 68 | 33 | 11 |

四门限同时稳定有 52 窗/25 序列/11 受试者；再要求 obs 平均水平速度 <.10 m/s，剩 51 窗/25 序列/11 受试者。它们仍是代理接触后反应的弱标签，不是唯一可识别的因果路线；299 窗也不是 299 个独立实验。

GT-local + unrestricted control oracle 在门后可逐帧追上 GT root，某些样本需要异常快的 catch-up 控制，不能视为自然运动。DCT8 oracle 的结果如下（水平 root RMSE 对三坐标分量平均后开根号，全部方法口径相同）：

| 门限 | 全 299 窗 mpjpe | 全窗 B 水平 root RMSE | 站定+四门限稳定 51 窗 mpjpe | 稳定子集 root RMSE |
|---|---:|---:|---:|---:|
| .15 | 0.01258 | 0.03819 | 0.00803 | 0.01127 |
| .20 | 0.00997 | 0.03114 | 0.00677 | 0.00764 |
| .25 | 0.00758 | 0.01653 | 0.00655 | 0.00715 |
| .30 | 0.00732 | 0.01575 | 0.00636 | 0.00681 |

.20 门下，GT-local oracle 全窗 8 条无法触发接触，稳定子集 0 条；稳定子集 unrestricted 响应控制 p95 为 .755 m/s、max 2.376 m/s，而全窗 max 7.550 m/s。这些 oracle 数字使用完整未来局部姿态、A root 与响应目标，不能与预测模型相提并论；只能说明稳定子集里低阶速度控制的表示损失并非首要障碍。

.15 门下稳定子集仍有单帧最大 7.434 m/s 的 catch-up 控制，说明事件迟触发可在积分器里被大速度补偿。进入训练之前必须设速度/加速度护栏和控制 oracle 自然度，不能仅优化 oracle L2。

## 固定 H-val 非学习型诊断

只读原先保存的 FD2 subject-val seed0/EMA10000 数组。强制全部 12 条推人走接触路线；不读取 GT 作为控制输入、不学习参数、不排除难例、不挑门限。GT 仅用于之后评价。

| 固定控制 | mpjpe | B 水平 root RMSE | 掌腕—身体距离 RMSE | 无预测接触窗 |
|---|---:|---:|---:|---:|
| 原 FD2 | 0.15544 | 0.07250 | 0.20269 | — |
| .15 门 | 0.17633 | 0.11810 | 0.23522 | 4/12 |
| .20 门（预固定主门限） | 0.16489 | 0.09487 | 0.23581 | 3/12 |
| .25 门 | 0.16400 | 0.09095 | 0.21959 | 1/12 |
| .30 门 | 0.15861 | 0.07868 | 0.20559 | 0/12 |

.20 门没有接触的三例：`S005C001P004R002A003`、`S007C001P027R002A003`、`S014C001P027R001A003`。A 手部计划来自 FD2，控制器让 B 暂停后也未到达预固定中心距；B 因而不能新增后退。曲线中其中两例 GT 确实明显后退，直接锁住 response 导致错误，而不是完成用户目标。

同一推人子集的步数为 0.429→0.429，完全没有增加左右交替；滑行帧比 0.465→0.408、GT 站定帧脚速 .135→.125 m/s、jerk 17.57→17.44，但这不能视为自然度成功，因为部分人的 root 被抑制导致脚也更少移动，paired L2 与接触距离均变差。保留腿局部轨迹只改变整个人的移动，不产生缺失的迈步。

## 后续边界

值得保留事件积分器作为可验证组件；当前证据不支持直接训练“先验手部+固定门+原腿”的完整方案。若继续，需要先新建实施设计同时解决：

1. A 手臂到达接触邻域的连续轨迹预测及事件控制标签（不能在漏接触样本上静默转自由路线）。
2. root 速度、起步/首脚状态、世界系站立脚锚的共同解码；纯 root 平移不会增加步数。
3. 路线不可识别性、置信度/覆盖与各路线全样本评价；真实避让数据不应硬锁死，失败案例也不能由自由路线掩盖。
4. 有界响应速度与低阶控制 oracle 的自然度审查，防止迟触发用 catch-up 突跳降低 L2。

暂不启动新的 GPU 训练矩阵，等待当前 C1–C4 固定实验完成并综合其证据；该状态不改变已经预登记的 C 实验。
